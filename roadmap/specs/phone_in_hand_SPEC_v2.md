# phone_in_hand スペックシート

## 1. 目的と想定用途

PC版VRChatで遊んでいる最中に、HMDを外さずに手元の実機スマホで調べ物をできるようにする。

- スマホの画面をPCに取り込み、SteamVRオーバーレイとして実物のスマホの位置に重ねて表示する。このパネルは自分にしか見えない
- 映像の取り込み方法は3つから選べる：HDMIキャプチャ（UVC）、Androidのミラーリング（USBかWi-Fi）、ウィンドウを取り込む（iPhoneはAirPlay受信ソフトと組み合わせる）
- 位置の基準は、既定ではスマホをホルダーでコントローラーに固定し、コントローラーの姿勢を使う。ハンドトラッキング（手の位置＋スマホの回転センサーの向き）はオプトイン
- 他のユーザーには、アバターの手にスマホの3Dモデルが見えるだけにする。画面の中身は送らない（同期パラメータで映像は送れず、プライバシーの面でも送らない）
- 利用者：一般のPC版VRChatユーザー。SteamVRで動くヘッドセットなら接続方法を問わない。主な端末はAndroid。iPhoneはワイヤレスデバッグなしで対応する

全体の構成は`phone_in_hand_system_overview.svg`を参照。

## 2. 機能要件

### PCアプリ

- 初回起動時に、映像→スマホ→VRChat→位置合わせの順にセットアップできる（S01）
- 映像の取り込み方法を選び、あとから設定で変えられる（S01a、S01f、S01g、S03a）
  - HDMIキャプチャ：デバイスと解像度・フレームレートを選び、プレビューで確かめられる。見つからない場合は理由と再試行を示す（S01a、S01b）
  - Androidのミラーリング：USBかWi-Fiと、映像の形式（自動ではH.265優先）を選べる。scrcpy-serverをADBでスマホに送り、受けた映像をPCでデコードする（S01f）
  - ウィンドウを取り込む：PC上のウィンドウを選んで映像にする。AirPlay受信ソフトは同梱しない（S01g）
- 映像の黒い余白を自動で切り抜け、手動にも切り替えられる（S01a、S01g、S03a）
- Androidのワイヤレスデバッグとペア設定でき、あとで設定することもできる（S01c）
- ハンドトラッキングを使う場合、センサー送信アプリをADBで入れて自動でつなげられる。手動で入れたアプリとは、QRコード（IPアドレス、ポート、接続トークン）かIPアドレスの入力でつなげられる（S01c）
- iPhoneの場合は、ワイヤレスデバッグとセンサー送信アプリなしで先へ進める（S01c）
- ロック解除の準備を案内できる。顔認証が使えないこと、回避方法（Androidは指紋・PINとExtend Unlock、iPhoneは「Apple Watchでロック解除」と自動ロックを「なし」にする設定）、画面を消さない設定は給電しながら使うこと。設定から見直せる（S01h、S03c）
- VRChatのOSCの受信と、アバターのパラメータの有無を確かめられる。この手順は飛ばせる（S01d）
- 位置の基準とスマホを付ける側（左右）を選び、VRの中で位置合わせできる。コントローラー固定では、ホルダーによる取り付けのずれ（位置と角度）を記録する。ホームからやり直せる（S01e、S02）
- ホームで、映像入力・スマホのセンサー・ワイヤレスデバッグ・位置の追跡・VRChatの5つの状態と、映像のプレビューを確かめられる（S02a〜S02c）
- ホームのスイッチで、VRへの表示をオン・オフできる（S02）
- 設定で、表示・位置・入力（ADB）・VRChat（ポートとパラメータ名）・一般（言語・テーマ・起動）を変えられ、次回の起動に引き継がれる（S03a〜S03c）

### VR内の表示

- 表示がオンのとき、パネルを実物のスマホの位置と向きに重ねる（S04a）。コントローラー固定では、コントローラーの姿勢と位置合わせの結果で決める
- ハンドトラッキングでは、手の位置とスマホの回転センサーの向きで決める。センサー値が途絶えたら手の向きで代用し、状態を示す（S04b、S02b）。ヨーのずれは手の向きを基準に緩やかに補正する
- 追跡が切れたら、最後の位置に止めて薄く表示し、戻れば元に戻す（S04c）
- スマホの画面が消えた（映像が黒い、信号・ミラーリングが途絶えた、取り込み元のウィンドウが閉じた）らパネルを隠し、画面がつけば戻す（S04e）

### ADB（Androidのみ）

- 使用中は「タップを表示」をオンにし、VRChatとOSCでつながっている間は画面を消さない設定にする。終了・切断・VRChatとの切断で元に戻す
- センサー送信アプリをADBでインストールし、接続情報を渡せる。Googleの開発者確認を受けていないアプリでも入れられる
- タッチ座標は読まない

### VRChat連携

- 表示中か（`PhoneInHand/Visible`、Bool）と持ち手が左か（`PhoneInHand/IsLeft`、Bool）をOSCで送る。パラメータ名は変えられる（S03b）
- OSCQueryで、VRChatの場所とアバターのパラメータの有無を調べる
- （初版のスコープ外。後の版で仕様変更として加える）アバター用パッケージで、Modular Avatarにより既存のアバターへ非破壊で組み込める。中身は2つのパラメータで切り替えるスマホの3Dモデルで、画面は固定の見た目（S04d）

### Androidのセンサー送信アプリ（ハンドトラッキング用）

- ADBで受け取った接続情報で自動でつながる。手動の場合はQRコードかIPアドレスでつなげられる（S05a）
- フォアグラウンドサービスで回転センサーの値を送り続け、送信中は通知を出す。ほかのアプリを使える（S05b）
- PCに届かない場合は、確認すべき点を示して再試行できる（S05c）
- バッテリーの最適化をオフにする設定画面を開ける（S05a）

## 3. 非機能要件

- 国際化の基盤を持つ。モード2で、初版から日本語・英語・中国語（簡体字、`zh-Hans`）に対応する。原文は日本語。PCアプリとAndroidアプリが対象
- 遅延：受け取ったフレームを次のSteamVRのフレームまでにオーバーレイへ反映する。CPUを経由するコピーは最小にする
- センサー：送信は60Hzが目安。途絶えてから1秒以内に手の向きでの代用へ切り替える
- 通信：PCとスマホの通信は同じLAN内（またはUSB）だけ。外部へは何も送らない。トークンが一致しないパケットは捨てる
- 保存：設定、ADBの鍵、位置合わせの結果は、PCのユーザー領域（Tauriのアプリデータのフォルダ）にだけ保存する
- 書体：IBM Plexの各書体はアプリに同梱し、実行時に外部から読み込まない（モックのGoogle Fontsの読み込みは引き継がない）
- アクセシビリティ：キーボードだけで操作でき、フォーカスが見える。状態は色と文字の両方で示す
- 既知の制限（READMEに書く）
  - コントローラー固定には、スマホのホルダーが別途必要
  - ハンドトラッキングは試験的。Meta Link（ケーブル・Air Link）では手の情報がPCに届かないため、Steam LinkかVirtual Desktopが必要。ハンドトラッキングのないヘッドセット（Rift Sなど）では選べない
  - HDMIではDRM付きの動画が映らない。ミラーリングでは取り込みを禁止したアプリが黒くなる
  - ミラーリングのWi-Fiとウィンドウの取り込みは、遅延が大きく画質がネットワークに左右される
  - HDMIキャプチャ中はUSB-Cポートがふさがるため、ADBはWi-Fi経由になる
  - センサー送信アプリはGoogleの開発者確認を受けない。APKを直接やObtainiumで入れると、Androidの追加の手順が必要になる（2027年以降、順次）
  - 顔認証は使えない。「Apple Watchでロック解除」は顔の覆い（マスク・サングラス・ゴーグル）向けの機能で、ヘッドセットで動くかは保証しない
  - iPhoneでは、「タップを表示」と画面を消さない設定を自動化できない。iPhoneでキャプチャ機器を使わない場合は、AirPlay受信ソフトが別に必要

|---|---|---|
| PCアプリ | Tauri 2系＋Bun＋TypeScript、Rustのバックエンド | 既定どおり。Tauri 2は安定版 |
| UI | SvelteKit（静的出力）＋carbon-components-svelte | Tauriと組み合わせた前例（OyasumiVR）がある。carbon-components-svelteはSvelte 5対応で更新が続いている |
| デザインシステム | IBM Carbon v11（g100・white） | PCとAndroidで共通。値は`tokens.css`の`--cds-*`が正 |
| PCのi18n | Paraglide JS 2系 | 型安全なキー、プレースホルダ、複数形に対応 |
| オーバーレイ | `ovr_overlay`（Rust） | 版は0.0.0で保守にリスクがある。足りなければC++の薄いサイドカーに切り替えてよい |
| 位置 | OpenVRのコントローラー姿勢（既定）、Skeletal Input | Steam LinkはQuestのハンドトラッキングをSkeletal Inputとして転送する |
| HDMIキャプチャ | `nokhwa` 0.10系（Media Foundation） | Windowsのバインディングは2025年11月に更新 |
| ミラーリング | scrcpy-server 4.1（Apache-2.0）＋Media FoundationのH.264・H.265デコーダー | プロトコルは内部仕様で、版の完全一致が必要。版を固定し、PCアプリと一緒に上げる |
| ウィンドウの取り込み | Windows.Graphics.Capture API | 任意のウィンドウをGPUのテクスチャとして受け取れる |
| ADB | `adb_client` 3.2系 | 純Rust実装で、ペア設定のAPIを持つ |
| OSC | `rosc` 0.11系、`vrchat_osc` 2系 | `vrchat_osc`はOSCQueryとmDNSでVRChatを見つけられる |
| Androidアプリ | Kotlin＋Jetpack Compose | `TYPE_GAME_ROTATION_VECTOR`（地磁気を使わない）をフォアグラウンドサービスで送る。種類は`connectedDevice`が第一候補 |
| Androidのi18n | string resources（`values`、`values-en`、`values-b+zh+Hans`） | 標準の仕組みで複数形も扱える |
| アバター用パッケージ（初版のスコープ外） | Unity 2022.3＋VRChat SDK3 Avatars＋Modular Avatar 1.18系 | 非破壊な組み込みと部品の配布のための道具。2026年11月時点で、VRChatのアバターはUnity 2022.3.22f1でのみ作れる |

既定から外れる点：PCアプリはWindows x64だけに対応する（SteamVRとPC版VRChatの利用環境のため）。

## 5. アーキテクチャ概要

構成図は`phone_in_hand_system_overview.svg`。PCアプリのRust側は次の責務に分け、モジュールの間はトレイトでつなぐ。テストでは偽の実装に差し替えられるようにする。

- `video_source`：映像のフレームを返す。実装は`hdmi_capture_source`、`android_mirror_source`、`window_capture_source`で、設定で切り替える
- `frame_processor`：切り抜き、黒い画面と信号断の検出（取り込み方法によらず共通）
- `pose_source`：基準の姿勢と追跡状態を返す。実装は`controller_pose_source`（既定）と`hand_pose_source`
- `phone_orientation_source`：Androidからの回転センサー値をUDPで受け、トークンを検証する（ハンドトラッキング時だけ）
- `pose_fusion`：パネルの姿勢を計算する。ヨーの補正、センサー途絶時の代用、追跡が切れたときの固定も担う
- `overlay_presenter`：姿勢と映像をオーバーレイへ反映する。表示・薄く表示・非表示の状態を持つ
- `adb_controller`：ペア設定、接続、アプリのインストール、設定の切り替えと復元、scrcpy-serverの起動
- `vrchat_bridge`：OSCの送信とOSCQueryの問い合わせ
- `settings_store`：設定と位置合わせの結果の保存
- `app_state`：各モジュールの状態をまとめてUIへイベントで通知し、UIからの操作をTauriのコマンドで受ける

映像は`video_source`→`frame_processor`→`overlay_presenter`と直接渡し、UIのプレビューには間引いた映像だけを送る。Androidアプリは、UI、接続設定、センサー送信サービスの3つに分ける。

原則：

- IBM Carbon v11に従う。ダークはg100、ライトはwhiteで、既定はシステムに合わせる
- PCアプリはcarbon-components-svelteの部品を使う。AndroidはCarbonの公式実装がないため、同じトークンをComposeのテーマに当て、見た目をモックに合わせる
- PCアプリのウィンドウは960×680、Androidアプリは幅360dpを基準にし、長い文字列でも崩れないようにする
- 状態は色と文字の両方で示し、フォーカスリングを常に見えるようにする

コンポーネント方針：Carbonの部品に対応させる。Button（Primary・Secondary・Ghost）、Select、TextInput、Toggle、Slider、Tabs（line）、状態の行（StructuredList相当）、InlineNotification（情報・注意・エラー）、ProgressIndicator、Tile、UI Shellのサイドナビ（アイコンだけのレール、幅48px。名前はツールチップとaria-labelで示す）、Link。通常・ホバー・フォーカス・無効の状態を持つ（S03c）。

アイコンの展開先：Windows（`.ico`とインストーラー）、Androidのアダプティブアイコン。Apple環境は対象外のため`.icon`は作らない。マスターSVGは、後から対象に加えられるレイヤー構成で描いてある。

確定事項（変更禁止）：トークンの値、画面構成（画面ID、各画面の要素と配置、画面遷移、描いた状態、どこに何の文言があるか）、マスターSVGとそのレイヤー構成、アイコンの余白ルール。

委任事項：モックの実装方式、ナビゲーションのアイコンをCarbonのアイコン（`@carbon/icons`のHomeとSettings）に置き換えること、各形式へのアイコンの展開、コンポーネントへのトークンの適用、縮小表示の確認、文言の言い回しと辞書のキー設計、アバター用の3Dモデルの形と作り方、ヨーの補正と黒い画面の検出のアルゴリズムと閾値。

## 7. 配布・公開方法

- バージョニングはSemVerで、初回は`0.1.0`。PCアプリとAndroidアプリは同じ版番号にそろえる（アバター用パッケージを加えるときも同じ版番号にする）
- リポジトリはpublic、ライセンスはApache-2.0。GitHub Releasesで配布する
  - PCアプリ：Windowsのインストーラー（tauri-action）。当面はコード署名をしない。READMEにSmartScreenの警告と進め方を書く。利用者が増えたらSignPath Foundationへの申請を検討する
  - Androidアプリ：署名済みのAPK。PCアプリに同梱してADBで入れる。Releasesにも置き、Obtainiumにも対応する。Google Playには出さず、Googleの開発者登録もしない
  - アバター用パッケージ：`.unitypackage`（初版のスコープ外）
- scrcpy-serverのライセンスと著作権表示を、NOTICEとアプリ内のライセンス表示に含める。GPLのソフトは同梱しない
- READMEに、導入手順、既知の制限、外部へ送信しないことを書く

## 8. スコープ外

- iOSアプリ（バックグラウンドのセンサー送信が位置情報の実行に頼らないとできず、審査の見込みが低い）
- macOS・Linux版、Quest単体版のVRChat
- スマホの画面の中身を他のユーザーに見せること
- タッチ座標の読み取り、ARCoreなどによるスマホ自身の6DoF推定
- AirPlayの受信機能の組み込み（受信ソフトの多くがGPLのため。ウィンドウの取り込みで代える）
- 初版（0.1.0）のアバター用パッケージ（S04d）。VRChatへのOSCの送信とパラメータの確認は初版に含める。パッケージは、後の版で仕様変更として加える

## 9. 未決定項目

- **ADBのペア設定にadbの本体が必要か**：`adb_client`がadbサーバーを前提にする場合、(a) platform-toolsを同梱する（導入は楽だが再配布の条件の確認が要る）、(b) 利用者に入れてもらう（手順が増える）
  - 決め方（プロジェクト・スタートで合意）：ADBのPhaseの最初に調査項目を置き、その結果で決める。`adb_client`はスペックの3.2系ではなく、その時点の最新版（2026年11月時点で4.0.0）で確かめる
- **アバター用パッケージの配り方**：(a) `.unitypackage`だけ（単純）、(b) VPMのリポジトリも用意する（ALCOMやVCCで更新が楽になるが、用意が増える）
  - 決め方（プロジェクト・スタートで合意）：パッケージを初版のスコープ外としたため、加える仕様変更のときに決める
- **フォアグラウンドサービスの種類**：`connectedDevice`の前提条件を満たせない場合に`specialUse`にするか（ストアに出さないので審査の影響はないが、OSの将来の制限に注意）
  - 決め方（プロジェクト・スタートで合意）：`connectedDevice`を第一候補とし、Androidアプリの実装で前提条件を公式ドキュメントで確かめる。満たせない場合だけ`specialUse`にする

## 9a. モックとの差分

アバター用パッケージを初版のスコープ外としたことによる、初版（0.1.0）での扱い（プロジェクト・スタートで合意）。

- S01d：「アバターへの組み込み方」のリンク（`wizard.vrchat.guide_link`）は表示しない。説明文（`wizard.vrchat.desc`）は、パラメータを持つアバターに着替える旨に言い回しを変える。OSCの受信とアバターのパラメータの確認は、そのまま残す
- S03b：「アバター用パッケージのフォルダを開く」（`settings.vrchat.open_package`）と「アバターへの組み込み方」は表示しない
- S04d：初版では実装しない（パッケージを加える版で実装する）

モックにない要素の追加（プロジェクト・スタートで合意）。

- S03c：一般タブの末尾に「ライセンス」のリンクを置き、同梱するソフトウェア（scrcpy-server、IBM Plexの書体ほか）のライセンスと著作権表示を一覧するダイアログ（CarbonのModal）を開く。7章の「アプリ内のライセンス表示」に当たる。文言は辞書に追加する

設定のタブの振り分けと、モックに描かれていない状態（v2で追加。`development/261116220850_change_settings_tabs.md`）。

- S03a：モックは表示タブに全項目を描いているが、項目をタブに振り分ける。表示：パネルの大きさ、明るさ、映像の取り込み方法、切り抜き。位置：位置の基準、スマホを付ける側。入力：「タップを表示」を自動でオンにする、スマホの画面を消さない
- S03a・S03b：保存ボタンは表示・位置・入力・VRChatのタブに出し、4つのタブの変更をまとめて保存する。一般のタブには出さない（S03cのとおり、変えた時点で保存して適用する）
- S03a：切り抜きの選択肢「手動」は、保存済みの値が手動のときだけ出す（手動の矩形は映像のページで指定するため、設定からは自動に戻すことだけができる）。取り込み方法の「Androidのミラーリング」は、iPhoneを使うときは出さない
- S03b：ポート（1〜65535の整数）とパラメータ名（空でない）の入力に誤りがあれば、入力欄に誤りを示す。誤りがあるまま保存を押すと、VRChatのタブへ移る
- S03：保存に失敗したときは、エラーの帯を出す
- S03c：言語の選択肢は、表示中の言語によらず、その言語自身の名前（日本語・English・简体中文）で出す
- S02：VRに表示の切り替えに失敗したときは、エラーの帯を出し、スイッチを実際の状態に戻す。映像のフレームがないときは、プレビューに空の状態（「映像がありません」）を出す
- S02：状態の行は、モックに描かれていない状態も、色と文字の両方で示す（映像の未接続・信号なし・取り込めない、ワイヤレスデバッグの未設定・タップを表示オフ、追跡が切れた、アバターのパラメータが見つからない、左右と位置の基準の組み合わせ）。文言は辞書に追加する
